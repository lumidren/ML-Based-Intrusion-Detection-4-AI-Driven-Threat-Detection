# Data Card

Two public testbed datasets from the Canadian Institute for Cybersecurity (CIC) are used.
Both were generated by replaying scripted benign "profiles" and launching real attack tools
against a victim network, capturing full packets, and summarising them into bidirectional
flows with CICFlowMeter v3. Neither contains real users' data.

The **measured** section at the end is generated by `nids data profile` from the files
actually used in this repository and is the authoritative description of what the models
saw. The narrative sections record provenance and the known problems that motivated the
clean-up rules in `src/nids/data/cleaning.py`.

### Known problems and how we handle them

| Problem | Evidence | Handling |
|---|---|---|
| Duplicated column `Fwd Header Length` (appears twice, identical values) | header inspection | second copy dropped (`DROPPED_2017`) |
| Label encoding glitch: `Web Attack � Brute Force` (en dash in cp1252) | header inspection | lossy-UTF-8 read, regex normalisation in `normalise_label` |
| `Infinity`/`NaN` in `Flow Bytes/s`, `Flow Packets/s` for zero-duration flows | ~2.9k rows | `inf` -> null, imputed from the *training* fold median |
| Exact duplicate flows (same 78 statistics and label) | 308,381 rows (10.9%), measured below | dropped before splitting so no vector appears in train and test |
| Negative `Flow Duration` (and therefore negative IAT/rate statistics) from timestamp wrap-around | 115 rows | rows dropped |
| Negative `min_seg_size_forward` (uninitialised value) | 35 rows | clipped to 0 |
| CICFlowMeter terminates TCP flows on the first FIN and mishandles RST, splitting one connection into several flows; attack flows are therefore fragmented and some "attack" rows are empty handshakes (Engelen et al. 2021; Lanvin et al. 2023) | literature; reproduced in our extractor's parity tests | we cannot re-label without the PCAPs; the paper reports results with and without single-packet attack flows; our own live extractor implements the *corrected* termination semantics and the parity test documents the delta |
| Thursday afternoon "Infiltration": only 36 labelled flows, while the actual infiltration (Dropbox download + Nmap sweep) generated far more traffic that is labelled BENIGN | Engelen et al. 2021 | day flagged `label_reliable=False`; excluded from training by default, reported separately |
| Destination port is a label proxy (each attack hits one fixed port) | per-port label purity, measured below | raw port is *not* a feature; replaced by a 3-level bucket |
| No timestamps in the ML CSVs, so temporal splitting must use row order | file inspection | row order follows flow completion order in CICFlowMeter output; we treat `row_id` as the time axis and group flows into blocks of 5,000 rows to avoid straddling bursts |
| Monday has no attacks; the Friday afternoon files overlap in time (PortScan then DDoS) | documentation | handled by per-file temporal splits and whole-day hold-outs |

### Known problems and how we handle them

| Problem | Evidence | Handling |
|---|---|---|
| Header row repeated inside several files | rows where `Dst Port == "Dst Port"` | filtered in `read_raw` |
| Column names differ from 2017 (`Tot Fwd Pkts` vs `Total Fwd Packets`, ...) | header inspection | `CSE2018_RENAME` to the canonical schema |
| Timestamps are `dd/mm/yyyy HH:MM:SS` local time with no zone | inspection | parsed as naive local time; used only for ordering and grouping |
| The "Infilteration" label on 28-02 and 01-03 marks *all* traffic of the victim host for hours, most of it ordinary (Liu et al. 2022) | literature | `label_reliable=False`; excluded from training by default |
| Files are capped at 1,048,575 rows (Excel limit) - the daily traffic was truncated, so days are *not* complete | row counts | documented; temporal splits are within-file |
| Many flows with `Dst Port 0`, `Protocol 0` and 3 packets (ARP/ICMP-like noise) | measured below | kept; they are legitimately benign background |
| Bulk statistics (`Fwd Byts/b Avg`, ...) and backward PSH/URG flags are constant | measured below | dropped (`DROPPED_2018`) to match the 2017 feature space |

## 3. Canonical schema

After canonicalisation both datasets share 68 flow statistics (`nids.data.schema.FLOW_FEATURES`),
a destination-port bucket, and metadata (dataset, day, row id, timestamp, IPs where present,
raw and canonical labels, coarse attack class, reliability flag). The canonical fine labels
and their coarse classes are in `nids.data.schema.LABEL_TO_CLASS`. Values are stored as
Float64 in zstd-compressed Parquet under `data/processed/canonical/<dataset>/<day>.parquet`.

## 4. Intended use and limitations

* **Intended:** research on flow-based intrusion detection, benchmarking detectors,
  studying cross-dataset generalisation (2017 -> 2018 and back).
* **Not intended:** estimating real-world false-positive rates. Testbed benign traffic is
  far less diverse than enterprise traffic; absolute FPR numbers will be optimistic.
* Attack tools are a 2017/2018 snapshot (Patator, Slowloris, LOIC, HOIC, Ares); novel
  attacks are not represented, which is why the system also ships an unsupervised score.
* Both datasets were produced with CICFlowMeter v3 whose TCP termination semantics are
  known to be wrong. Models trained here learn those semantics; our live extractor is
  therefore run in a *compatibility* mode by default (see `nids.features.flow`).
